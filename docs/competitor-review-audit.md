# 경쟁사 리뷰 대응 (유니브 AI, com.ai.univai)

2026-09-07에 Google Play 리뷰 78개를 수집해 분류했습니다. 원문은
`scratchpad/reviews.json`, 이 문서는 각 불만에 대해 우리가 무엇을 했는지입니다.

## 불만 순위와 대응

### 1. 자료에 없는 문제, 틀린 정답, 중복 문제 (10건 이상, 1위)

> "pdf에 없는 내용으로 문제가 구성되네요. 설정에 pdf에 있는 내용으로만 하라고 적어도 그대로고"
> "계속 유사한 문제만 내길래 범위 조정까지 했는데도 계속 같은 문제만"
> "자료에 있는 내용도 틀렸다는 퀴즈를 만들고, 없는 내용 만드는 것도 짜증나는데"

프롬프트로 부탁하는 방식은 이미 실패한 방식입니다. 그래서 **서버가 대조**합니다.

- 모델이 문제와 개념마다 `evidence`(근거가 된 원문 문장)를 그대로 인용하게 합니다.
- `app/ai/grounding.py`가 그 문장이 실제 대본이나 문서에 있는지 대조합니다. 없으면
  그 항목을 버립니다. 음성 인식 문장은 모델이 문장부호를 다시 찍으므로 완전 일치가
  아니라 4글자 단위 겹침 60% 이상으로 판정합니다.
- 중복은 문장 유사도만으로 판정하지 않습니다. "분류는 무엇을 예측하나요"와 "회귀는
  무엇을 예측하나요"는 유사도 0.75지만 서로 다른 문제라서, 유사도가 0.85 이상이거나
  (0.6 이상이면서 정답이 같을 때)만 중복으로 봅니다. 실제 문장으로 임계값을 맞췄습니다.
- 근거를 못 대는 항목이 전부면 자료를 저장하지 않습니다. 억지로 개수를 채우지 않습니다.
- 테스트 14개(`tests/test_grounding.py`)로 고정했습니다.

### 2. 결제와 환불 (10건, 2위)

> "인앱에서 구독취소를 했는데 다음달에 결제가 되었어요. 플레이스토어에서는 구독취소가 안되어있더라고요"
> "환불받으려고 환불페이지에 가도 환불가능 결제 내역이 없어" / "고객센터도 없어서"

2026-09-07에 인앱 결제로 결정했으므로, 경쟁사가 겪은 사고를 구조로 막습니다.

- **앱 안에 자체 해지 화면을 두지 않습니다.** 경쟁사 사고의 원인은 앱이 "구독 취소
  예정"이라고 표시했지만 Play에는 반영되지 않은 것이었습니다. 우리 구독 관리 행은
  Play 구독 설정 화면을 직접 엽니다. 앱이 해지 상태를 자기 말로 주장하지 않으므로
  앱과 스토어가 어긋날 수 없습니다.
- 결제 상태는 스토어가 원본이고, RevenueCat 웹훅으로 계정에 반영됩니다. 결제 직후에는
  앱이 서버에 직접 조회를 요청해 웹훅을 기다리지 않습니다.
- 해지해도 기간이 끝날 때까지 스탠다드가 유지됩니다. 서버가 해지 이벤트로 요금제를
  내리지 않고, 만료 이벤트로만 내립니다. 돈을 낸 만큼은 쓰게 합니다.
- 구독 화면이 현재 요금제, 다음 갱신일, 이번 달 사용량을 보여 주고 구매 복원 버튼이
  있습니다. 문의 경로는 support@camorix.com.

### 3. 속도와 안정성 (8건, 3위)

> "요약하다가 중간에 앱이 종료" / "퀴즈 생성에는 20분 이상" / "오류가 계속 떠서 분석도 못했습니다"

- 처리 화면이 단계별 진행과 예상 순서를 보여 주고, 실패하면 원인별 문구와 재시도를 줍니다.
- 전사는 구간이 실패하면 재시도, 반으로 분할 재시도, 그래도 안 되면 전체를 한 번에 읽어
  빈 구간을 메웁니다. 한 구간의 실패가 자료 전체를 잃게 만들지 않습니다.
- 요약, 상세 요약, 복습 자료, 평가는 모두 실패해도 대본을 지키는 최선 노력 단계입니다.

### 4. 모바일 버그 (5건)

> "휴대폰으로 쓰면 ai한테 물어볼 때 한글 자판이 안 쳐지고" / "폰으로는 선택을 하는 옵션이 잘리네요"
> "갤럭시탭에서 가로 모드 지원" / "구글아이디 로그인 누르면 앱 업데이트하거나 다시 시도하라고"

- 키보드가 입력창을 가리던 문제를 고쳤습니다. 채팅은 별도 화면이고 입력창은 스크롤 밖에
  고정되며, 안드로이드 edge-to-edge에서도 키보드 높이만큼 올라옵니다.
- 하단 잘림은 안전 영역 규칙을 문서화하고 모든 화면에 적용했습니다.
- 태블릿 가로 모드를 켰습니다.

### 5. 백그라운드 녹음 (가장 최근 리뷰)

> "화면 유지시에만 녹음이 되던데요. 녹음 동시에 삼성노트앱을 사용 했더니 녹음이 하나도 안되었어요"

우리는 포그라운드 서비스와 알림 권한으로 화면을 끄거나 다른 앱을 써도 녹음이 이어집니다.
경쟁사가 못 하는 것이고, 강의 녹음에서는 이게 전부입니다.

## 칭찬받은 기능과 우리 상태

| 경쟁사가 칭찬받은 것 | 우리 |
| --- | --- |
| 자료 기반 요약, "쉽게 풀어 설명" | 요약 + **상세 요약**(구간별 3~6문장, 다시 안 들어도 되는 분량) |
| 자료 기반 문제 출제 | 있음, 근거 검증 포함 |
| 퀴즈 결과로 강약점 | 이해도 탭(취약 개념, 다시 들을 시점) |
| 마인드맵 | 있음 |
| AI 튜터(질문) | 있음, 서버가 대본을 읽고 자기 말로 답하며 근거 시점을 붙임 |
| **PDF 요약과 퀴즈** | **추가함**. PDF와 슬라이드를 쪽 단위로 읽어 같은 파이프라인에 넣습니다 |
| 플래시카드, 암기 | 추가함. 자료 상세의 카드 탭, 개념과 칠한 문장으로 덱을 만듭니다 |
| 요약에 형광펜, 필기 | 추가함. 탭 한 번으로 칠하고, 칠한 문장이 목록과 암기 카드가 됩니다 |

## PDF와 슬라이드

`app/recordings/document.py`가 업로드된 PDF(pypdf)와 슬라이드(python-pptx)를 쪽 단위로
읽습니다. 음성 전사만 건너뛰고 나머지는 동일합니다. 쪽 번호는 녹음의 밀리초 자리에
실려서(1쪽은 0, 2쪽은 1000) 기존 코드가 그대로 동작하고, 프롬프트만 `(3쪽)` 표기와
"쪽 번호"라는 말을 쓰도록 갈라집니다. 글자가 없는 스캔 PDF는 "스캔한 이미지 PDF는 아직
읽을 수 없어요"로 정직하게 실패합니다.

운영 서버 확인(2026-09-07): 3쪽 PDF 업로드 → 요약, 핵심 3개, 개념 3개, 문제 4개,
상세 요약 3구간이 모두 올바른 쪽 번호와 함께 생성됐습니다.
